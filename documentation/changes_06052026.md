# Local Network Development Setup

This document explains how to run the app locally on a MacBook and access it from another device connected to the same Wi-Fi network.

## Problem

The frontend was accessible through the MacBook, but login failed from another device with:

```text
Failed to fetch
```

The backend was working correctly when accessed directly through:

```text
http://192.168.254.112:8000/docs
```

The issue was not backend authentication logic. The issue was the frontend-to-backend browser request across different origins:

```text
Frontend: http://192.168.254.112:3000
Backend:  http://192.168.254.112:8000
```

Even though both use the same IP address, the ports are different, so the browser treats them as different origins.

## Root Cause

The frontend needed the correct LAN-accessible backend URL.

Using `localhost` or `127.0.0.1` does not work from another device because those addresses point to the device opening the browser, not the MacBook running the server.

Incorrect:

```env
NEXT_PUBLIC_API_URL=http://localhost:8000
```

Correct:

```env
NEXT_PUBLIC_API_URL=http://192.168.254.112:8000
```

## Frontend Environment Variable

Create this file:

```bash
frontend/.env.local
```

Add:

```env
NEXT_PUBLIC_API_URL=http://192.168.254.112:8000
```

The frontend API client uses:

```ts
export const API_BASE_URL =
  process.env.NEXT_PUBLIC_API_URL ?? "http://192.168.254.112:8000";
```

Important: the variable name must match exactly:

```env
NEXT_PUBLIC_API_URL
```

Not:

```env
NEXT_PUBLIC_API_BASE_URL
```

## Frontend API Client

The request wrapper should call the backend using `API_BASE_URL`.

```ts
import { clearSession, getToken } from "./auth";

export const API_BASE_URL =
  process.env.NEXT_PUBLIC_API_URL ?? "http://192.168.254.112:8000";

type RequestOptions = RequestInit & { skipAuth?: boolean };

async function request<T>(path: string, options: RequestOptions = {}): Promise<T> {
  const token = getToken();
  const headers = new Headers(options.headers);

  if (!(options.body instanceof FormData)) {
    headers.set("Content-Type", "application/json");
  }

  if (token && !options.skipAuth) {
    headers.set("Authorization", `Bearer ${token}`);
  }

  const response = await fetch(`${API_BASE_URL}${path}`, {
    ...options,
    headers,
    mode: "cors",
  });

  if (response.status === 401) {
    clearSession();

    if (typeof window !== "undefined") {
      window.location.href = "/login";
    }
  }

  if (!response.ok) {
    const body = await response.json().catch(() => ({}));
    throw new Error(body.detail || "Request failed");
  }

  if (response.status === 204) {
    return undefined as T;
  }

  return response.json() as Promise<T>;
}

export const api = {
  get: <T>(path: string) => request<T>(path),

  post: <T>(path: string, body: unknown, options?: RequestOptions) =>
    request<T>(path, {
      method: "POST",
      body: JSON.stringify(body),
      ...options,
    }),

  put: <T>(path: string, body: unknown) =>
    request<T>(path, {
      method: "PUT",
      body: JSON.stringify(body),
    }),

  delete: <T>(path: string) =>
    request<T>(path, {
      method: "DELETE",
    }),
};
```

## FastAPI CORS Configuration

The backend must explicitly allow the frontend origin.

```python
from fastapi.middleware.cors import CORSMiddleware

origins = [
    "http://192.168.254.112:3000",
    "http://localhost:3000",
    "http://127.0.0.1:3000",
]

app.add_middleware(
    CORSMiddleware,
    allow_origins=origins,
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

Do not use this combination:

```python
allow_origins=["*"]
allow_credentials=True
```

Browsers reject wildcard origins when credentialed requests are involved.

## Next.js Dev Origin Configuration

For Next.js 15, configure allowed development origins.

In `frontend/next.config.js`:

```js
/** @type {import('next').NextConfig} */
const nextConfig = {
  allowedDevOrigins: [
    "192.168.254.112",
    "192.168.254.112:3000",
  ],
};

module.exports = nextConfig;
```

## Start Backend

Run the backend on all network interfaces:

```bash
cd backend
venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Backend should be accessible from another device at:

```text
http://192.168.254.112:8000/docs
```

## Start Frontend

Run the frontend using the MacBook Wi-Fi IP:

```bash
cd frontend
rm -rf .next
npm run dev -- -H 192.168.254.112 -p 3000
```

Frontend should be accessible from another device at:

```text
http://192.168.254.112:3000
```

## Restart Commands

When changing `.env.local`, `next.config.js`, or CORS settings, restart the servers.

Restart frontend:

```bash
cd frontend
kill -9 $(lsof -ti tcp:3000) 2>/dev/null || true
rm -rf .next
npm run dev -- -H 192.168.254.112 -p 3000
```

Restart backend:

```bash
cd backend
kill -9 $(lsof -ti tcp:8000) 2>/dev/null || true
venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## Automation Script Notes

The automation script should detect the MacBook Wi-Fi IP:

```bash
LAN_IP="$(ipconfig getifaddr en0 || true)"
```

The backend should run with:

```bash
venv/bin/uvicorn app.main:app --host 0.0.0.0 --port "$BACKEND_PORT"
```

The frontend should run with:

```bash
env NEXT_PUBLIC_API_URL="http://$LAN_IP:$BACKEND_PORT" \
  npm run dev -- -H "$LAN_IP" -p "$FRONTEND_PORT"
```

The script should print LAN URLs:

```bash
echo "Frontend LAN: http://$LAN_IP:$FRONTEND_PORT"
echo "Backend LAN:  http://$LAN_IP:$BACKEND_PORT"
echo "API docs LAN: http://$LAN_IP:$BACKEND_PORT/docs"
```

## Troubleshooting

Check the MacBook Wi-Fi IP:

```bash
ipconfig getifaddr en0
```

Check frontend port:

```bash
lsof -nP -iTCP:3000 -sTCP:LISTEN
```

Check backend port:

```bash
lsof -nP -iTCP:8000 -sTCP:LISTEN
```

Test backend from another device:

```text
http://192.168.254.112:8000/docs
```

Test frontend from another device:

```text
http://192.168.254.112:3000
```

If backend `/docs` works but frontend login returns `Failed to fetch`, check:

1. `frontend/.env.local` uses `NEXT_PUBLIC_API_URL=http://192.168.254.112:8000`
2. Frontend was restarted after changing `.env.local`
3. FastAPI CORS includes `http://192.168.254.112:3000`
4. Frontend is not calling `localhost:8000`
5. Backend is running with `--host 0.0.0.0`
6. Frontend is running with `-H 192.168.254.112`
